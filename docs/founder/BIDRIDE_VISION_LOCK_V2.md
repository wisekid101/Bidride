*(Sources: `founder-profile.md`, memory `founder_markie_brown`, discovery report §1/§5/§6.)*

## 2. Company Constitution

**Company facts.** Name **BidiRide** (locked docs) / **BidRide** (directives) — see C‑1. Delaware LLC · HQ New Jersey · Launch market Newark/EWR · Bootstrapped · Founder‑only team · iOS + Android (React Native + Expo) on a single backend, built from day one for millions of rides/month.

**Mission.** *To create the most driver‑friendly, rider‑friendly, and AI‑powered transportation marketplace in America.* Operating priorities, in order: ① **Safety before growth** ② **Trust before speed** ③ **Long‑term sustainability before short‑term profit.**

**Vision — horizons** *(phase set locked; dates illustrative):*

**Company identity.** BidRide is *the world's smartest, fairest, AI‑governed movement marketplace.* It is **NOT** an Uber clone, a Lyft clone, a social network, or a random super‑app (see §29, §26).

## 3. Product Constitution
*(Permanent product law. Sources: discovery report §5/§7/§13, `product-vision.md`, `pricing-model.md`, Founder directive.)*

1. **Standard rides are FIRST — the primary experience.** Default flow: pickup/destination → **AI‑recommended fare** → accept (instant, familiar). This is the spine and is never subordinated.
2. **Bidding ("BidRide Offer") is OPTIONAL — a power feature, never required.** "BidRide is not primarily a bidding platform." Rider may Accept / Offer‑lower / Priority / Premium; driver may Accept / Decline / Counter — **always within AI‑enforced bounds**; every bid has a **floor that protects driver earnings**; no rider bid overrides driver protection; the platform prevents race‑to‑the‑bottom.
3. **Driver earnings are prioritized.** 70–80% take‑home; deterministic per‑trip earnings floor; instant payout; driver take‑home shown **first and largest**.
4. **AI is advisory before autonomous.** AI recommends; human‑defined rules decide; shadow mode is the default posture; autonomy only by explicit Founder approval after evidence.
5. **Safety before growth. Trust before speed.** No growth target overrides a safety or trust decision.
6. **Community before advertising.** Community is purpose‑driven (trust/safety/local movement), never an attention/ad engine.
7. **Business tools before vanity features.** Real B2B/local‑business value is sequenced ahead of cosmetic additions.
8. **No fake anything.** No fake surge · no hidden fees · no fabricated data · no vanity UI without a real backend · no unsupported screens.
9. **Never rewrite approved work.** Build forward from what is merged and validated.

# PART II — THE CONSTITUTIONS

## 6. Engineering Constitution
*(Founder directive + this project's proven working style.)*
Never rewrite approved architecture or replace approved systems · **build forward** · small, independently‑mergeable, reversible milestones · **real tests, real demos, real validation — evidence before assertions** · **no placeholders, no fake APIs, no fake UI, no skipped testing** · additive over destructive; preserve backward compatibility until a full migration is Founder‑approved · every nontrivial change is proven by *running* it · confirm before hard‑to‑reverse/outward actions; commit/push/deploy only on explicit Founder approval.

## 7. Design Constitution
*(Sources: `CLAUDE.md` design system, discovery report §9.)*
- **Brand:** premium, modern, intelligent, trustworthy, driver‑first. **Positioning:** more premium than Uber, more approachable than Lyft. Values: fair pricing, smart tech, transparency, safety, opportunity.
- **Color system (locked):** Deep Navy `#0A2342` (foundation/trust) · Electric Teal `#00D4C6` (intelligence/AI/movement) · **Gold `#F4B400` — earnings ONLY** · Safety/SOS Red `#EF4444` (SOS/safety only) · text on Teal must be **Navy** (white‑on‑teal fails WCAG AA).
- **Typography:** `JetBrains Mono` for **all** dollar amounts; `Inter` for body.
- **Motion/animation:** smooth, purposeful (e.g., follow‑camera `animateCamera` with a 12 m jitter floor + ~900 ms throttle — see Mobile §9); never gratuitous.
- **Map/GPS behavior:** follow‑camera keeps the vehicle centered while moving; pause‑on‑user‑pan; Recenter control resumes; no map remount per GPS update; heading applied only when valid.
- **Accessibility:** WCAG‑aware; intentional exclusions (panic gesture) are deliberate and documented.
- **Micro‑interactions / loading / offline:** consistent, production‑quality; graceful loading and offline/degraded states; visual consistency across both apps + portal.
- **Change rule:** no redesign/re‑theme/navigation overhaul without explicit Founder approval.

## 8. UX Constitution
*(Sources: `product-vision.md`, `CLAUDE.md`, discovery report §13.)*
Familiar Uber/Lyft‑equivalent core flow so nothing feels foreign · **driver take‑home first and largest** on every driver surface · transparency by default (rider sees the price they'll pay; no hidden fees) · optional power features (bidding, priority, premium) never clutter the default path · safety is one tap away and never obstructed · trust is shown as **badge labels, never numbers** · every visible control maps to a real capability.

## 9. Mobile Constitution
*(Sources: `CLAUDE.md`, `design/mobile-acceptance-harness.md`, merged mobile milestones.)*
Two dedicated apps — **BidRide Rider** and **BidRide Driver** — React Native + Expo, one shared backend, reached through the dev‑proxy/ALB routing · Expo Router file‑based navigation · auth via OTP (SecureStore for tokens, never AsyncStorage) · driver flows: onboarding → Drive/Earnings/Profile, incoming request, in‑trip, airport mode · rider flows: home/booking, tracking, SOS, trip‑complete, bid‑request, trusted contacts · **follow‑camera + Recenter** on active‑trip maps (identical hook in both apps) · stable `testID`/a11y hooks for acceptance automation **without changing behavior or visuals** · driver location via `watchPositionAsync` → socket + heartbeat; change‑triggered GPS stream · apps must build/run through Expo Go and pass the Maestro acceptance harness. Store publishing, physical‑device SOS validation, and prod API base URL are **launch‑gated** (production‑readiness).

## 10. AI Constitution
*(Sources: discovery report §15, `design/ai-core-architecture.md`, `design/ai-intelligence-layer.md`, `design/ai-governance-rules.md`, AI Core as shipped: Phases 1/2/3.1/3.2.)*

**Prime rule — recommend‑first.** The AI Core **never executes a business decision.** It returns advisory values; platform code owns every clamp, cap, and floor. **The marketplace runs correctly with the AI Core completely offline.** Shadow mode is the **default posture** (`ai_shadow_mode` default TRUE — verified live). Autonomy is enabled only per‑capability, only by explicit Founder approval, only after evidence.

**AI hard rules (governance):** never manipulate pricing against users · never suppress driver earnings below the floor · never create artificial surge · safety‑affecting AI requires human‑review capability · **every recommendation is explainable, evidence‑backed, confidence‑scored, and auditable** · data is never sold; insights serve only driver earnings and rider experience; all improvements pass the Five Decision Tests.

**The AI engines / surfaces (each advisory, each governed):**
- **Pricing AI** — recommended fares within bounds; enforces (via platform code) the deterministic earnings floor; no artificial surge.
- **Dispatch AI** — recommends matching/positioning; **dispatch remains rule‑based**; AI never overrides safety/eligibility.
- **Fraud AI** — risk scoring; auto‑hold ≥90%; **human‑only** permanent decisions.
- **Marketplace AI** — monitors overall marketplace health/balance.
- **Community AI** — moderation assistance with human review (§17).
- **Driver AI / Rider AI** — positioning guidance; demand anticipation.
- **Business AI** — corporate optimization (future, §18).

**Learning loop / flywheel:** completed trip → more data → better predictions → happier drivers → more drivers → faster pickups → more riders → more trips. Evidence, confidence, and outcome‑evidence are recorded in the intelligence ledger; the Founder portal Intelligence surface is **read‑only** ("adopting a recommendation records your decision; it never executes a change").

**Production rollout of AI:** shadow → measured → Founder‑approved, per capability. Pricing stays deterministic; the earnings floor is never ML‑overridden.

## 11. Safety Constitution
*(Sources: discovery report §16, `CLAUDE.md`, `docs/legal-safety-requirements.md`, founder‑gates panic protocol.)*
Safety is a **pillar, not a feature**; **safety decisions override all other decisions**. Driver verification: gov‑ID, pre‑shift biometric selfie, professional background check (Checkr), vehicle inspection/registration, ongoing MVR monitoring. Rider verification: phone/email baseline, risk scoring, behavioral monitoring. Trip safety: live AI monitoring, real‑time GPS, **SOS (3‑state: initiate → 5s countdown → confirm)**, 911 integration, trusted contacts live link, family tracking, **audio only on SOS confirm** (encrypted, consent‑compliant per state), route‑deviation/anomaly detection. **Panic (non‑negotiable):** triple‑tap, single vibration, no visual change, **not in the accessibility tree**; admin payload contains **no `riderId`/`riderName`/`riderPhone`**; admin must not contact the rider during a panic event; any panic‑schema change requires Founder sign‑off; violations are safety incidents. NJ mandates: zero‑tolerance policy (disclosed + acknowledged), accessibility, non‑discrimination.

## 12. Trust Constitution
*(Sources: `CLAUDE.md`, discovery report §23.)*
Trust is BidRide's **identity**. Trust scores are **internal only** — never expose numeric scores to riders or drivers (anti‑discrimination). Only **four visible badge labels**: Verified, Trusted, Business (riders), VIP. Fraud auto‑hold ≥90% probability; **no automated permanent ban** — human admin required; automated flags feed a human‑review pipeline. Audit logs are append‑only. Trust is earned before growth is pursued.

## 13. Payments Constitution
*(Sources: `CLAUDE.md`, `production-readiness.md`, founder‑gates `wallet_hold_hours`, `pricing-model.md`. Note C‑7, C‑8.)*
Stripe Connect for driver payouts; **PCI scope minimized** via Stripe Elements/hosted fields (no raw card data on BidRide servers); **verified Stripe webhooks** (`constructEvent` + `STRIPE_WEBHOOK_SECRET`). **Idempotent** money operations (per‑trip charge, capture, payout, batch keys; Stripe event dedup) — no duplicate charges or ledger rows. **Instant payout** with a driver wallet **2‑hour hold** (`wallet_hold_hours`, Founder‑restricted). Instant payout is **FREE** — no fee is charged, deducted, recorded, or displayed (Founder ruling 2026‑07‑31; C‑7 RESOLVED, GAP‑019 CLOSED). $10 min, $500 cap, 2h hold remain. Commission is 20–30% (driver 70–80%); the **exact base commission rate and bid‑floor formula remain open** (`pricing-model.md` open questions — C‑8). Never monetize data, artificial surge, hidden fees, or driver‑earnings suppression.

Preferred‑driver relationships and driver subscriptions are **proposed (pending approval)** — see §16/§26 and C‑9.

Account deletion / PII purge and ToS/Privacy in‑app are **launch‑gated** compliance items.

## 20. Data Constitution
*(Sources: discovery report §7/§15, `CLAUDE.md`, `database-architecture.md`.)*
**Data is never sold.** Flywheel insights serve only driver earnings and rider experience. Money in `Decimal`; single‑currency today; region/market and multi‑currency are **deferred** (add when a second market/country arrives — see architecture reviews). ## 21. Security Constitution
*(Sources: `CLAUDE.md`, founder‑gates, `technical-architecture.md`, production‑readiness.)*
Auth: OTP + JWT + MFA (TOTP + FIDO2). Rate limiting (`@nestjs/throttler`) on user‑facing services. Secrets in AWS Secrets Manager + KMS; **no secrets in git**. Inter‑service auth via internal service key (rotation is a Founder‑gated change). CORS allowlist (WS origins must be set in prod). WAF, managed HTTPS/ACM, alerting are **launch‑gated infra**. Security‑policy changes (JWT/OTP/rate‑limit/CORS/WebAuthn/audio‑trigger) require **Founder review** (founder‑gates). MFA enforcement on admin is a required hardening item.

## 22. Observability Constitution
*(Sources: `packages/observability`, Sprint 1 Batches 1–2, `production-readiness.md`.)*
Every service is observable via the shared **`@bidride/observability`** library and its **`/nest`** adapter: **AsyncLocalStorage correlation IDs** propagated through async execution and echoed as `x-correlation-id`; **structured JSON request logging** with **PII redaction** (passwords, OTPs, tokens, authorization, cookies, SSNs, CVVs, card data) and **no request/response bodies logged by default**; shared HTTP metrics; **additive** `/live` (liveness) + `/ready` (readiness) + `/metrics` (Prometheus) endpoints while existing `/health` semantics are **preserved during migration**. Rollout is one service at a time (auth pilot; notification/airport/trust done). CloudWatch dashboards + SNS/on‑call alerting are the current Sprint‑1 continuation. You cannot operate a safety‑critical marketplace blind — observability precedes scale.

## 23. Testing Constitution
*(Sources: this project's test suites, `design/mobile-acceptance-harness.md`, `regression-suite.md`.)*
Real tests only — **no fakes, no skipped testing**. Unit tests per service; integration tests against a **safe throwaway test DB** (never `bidride_dev`); e2e via **Maestro** simulator flows + the GPS harness (drive real UI, never substitute backend APIs for user transitions); resource‑safe execution (one package at a time when memory‑constrained). PII‑redaction, correlation, and no‑duplicate‑metrics are explicitly tested. Coverage expands to auth/payment/driver integration suites and mobile Maestro flows as a milestone.

## 26. Full Product Description
*(Each surface: WHY it exists · HOW it works · value · differentiation. Grounded; DRAFT items flagged.)*

- **Rider onboarding** — *Why:* frictionless, trusted entry. *How:* phone OTP → profile → payment method (Stripe) → optional trusted contacts. *Value/Diff:* familiar + transparent + safe from step one.
- **Driver onboarding** — *Why:* only verified, compliant partners. *How:* OTP → personal info → vehicle → document upload (S3) → bank (Stripe Connect) → background check (Checkr, FCRA workflow) → zero‑tolerance ack → W‑9. *Diff:* driver‑first economics visible during onboarding.
- **Business onboarding** *(future, §18)* — corporate accounts, employee ride policies, billing/expense.
- **Founder dashboard / Intelligence portal** — *Why:* Founder control + AI oversight. *How:* **read‑only** Intelligence (recommendations with evidence, confidence, expected value, reasoning, safety impact, outcome evidence, Founder scoring, AI performance, Focus Brief); Founder‑gated config (earnings floor, surge cap). *Diff:* AI is transparent and advisory, never autonomous.
- **AI dashboard** — recommendation inbox/detail, calibration, model performance, shadow‑mode status.
- **Admin dashboard** — live operations, GMV, Safety Center, Fraud (no automated bans), Earnings‑Floor (Founder‑only lock), Drivers, Refunds; role hierarchy Founder → Super → Operations → Safety → Driver‑Approval → Fraud → Support → Analytics.
- **Wallet (Move Money)** *(directive‑new pillar, C‑4)* — driver balance, 2‑hour hold, instant payout; future rider wallet. *Diff:* fee‑free instant pay is a driver moat (fee policy pending, C‑7).
- **Payments** — Stripe Connect, verified webhooks, idempotent charge→capture→payout, earnings‑floor supplement, platform fee. (See §13.)
- **Subscriptions / Preferred Drivers** — **DRAFT, pending Founder approval (C‑9):** Preferred Driver Network, BidiRide Connect, Driver Following, Driver Subscription Plans, Driver Business Center, Corporate Preferred Driver Program — a relationship/loyalty layer shifting BidRide from price‑matching toward a trusted‑network platform. **Do not build without explicit approval.**
- **Airport mode (EWR)** — *Why:* the anchor market. *How:* FIFO virtual queue (Redis sorted set), FlightAware 30s cache, surge cap 2.5× (admin confirm >1.5×), pickup‑zone config, Port‑Authority fee ledger (launch item). *Diff:* purpose‑built for EWR.
- **Marketplace** — dual‑mode pricing + relationship layer (§16).
- **Community** — neighborhood, safety, local marketplace, feature voting, AI moderation (§17).
- **Move People / Move Goods / Move Money** — the pillar trilogy (§4), sequenced by §28.
- **Future Enterprise Platform** — fleet/freight/managed logistics (§19).
